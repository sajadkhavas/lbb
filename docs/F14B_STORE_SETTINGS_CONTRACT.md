# F14B — Store Settings Contract

## هدف

این قرارداد مرز میان اطلاعات عمومی فرانت‌اند، تنظیمات پنل ادمین و اطلاعات محرمانهٔ بک‌اند را مشخص می‌کند. فرانت‌اند فقط داده‌ای را نمایش می‌دهد که هم فعال و هم تأیید شده باشد.

## اصل نمایش

هر قابلیت عملیاتی سه وضعیت دارد:

- `verified`: داده از منبع رسمی کسب‌وکار تأیید شده است.
- `pending`: داده وارد شده، اما هنوز نباید عمومی شود.
- `missing`: داده وجود ندارد.

تنها مورد `verified` همراه با `isEnabled: true` اجازهٔ تولید ادعا در رابط عمومی دارد.

## داده‌های عمومی قابل دریافت از پنل

### مکان فروشگاه

- کشور، استان، شهر و نام مجتمع
- طبقه و واحد
- نشانی نوشتاری
- کد پستی
- مختصات
- ساعت کاری
- وضعیت عمومی‌بودن و تأیید

در وضعیت فعلی فقط «کرج، پاساژ مهستان» تأیید شده است.

### راه‌های ارتباطی

- اینستاگرام
- تلفن
- ایمیل
- واتساپ

هر کانال باید نشانی قابل استفاده، برچسب فارسی، وضعیت عمومی‌بودن و وضعیت تأیید داشته باشد.

### ارسال

- عنوان و توضیح روش ارسال
- هزینه
- حد ارسال رایگان
- زمان پردازش
- بازهٔ تحویل
- استان‌های تحت پوشش
- امکان رهگیری

تا زمان تأیید، هیچ مبلغ یا بازهٔ زمانی در رابط عمومی نمایش داده نمی‌شود.

### تعویض و مرجوعی

- فعال‌بودن تعویض
- فعال‌بودن مرجوعی
- مهلت درخواست
- زمان بازپرداخت
- مسئول هزینهٔ بازگشت
- کالاهای مستثنا

مقادیر ساختگی یا قانون عمومی حدس‌زده‌شده مجاز نیستند.

### پرداخت

داده‌های عمومی فرانت‌اند:

- فعال‌بودن
- نام ارائه‌دهنده
- عنوان نمایشی
- آیکون
- روش‌های پرداخت فعال
- مسیر Callback

اطلاعات زیر فقط سمت سرور نگه‌داری می‌شوند:

- Merchant ID محرمانه
- API Key
- Client Secret
- Private Key
- Webhook Secret
- امضای درخواست
- دادهٔ Verify تراکنش

فرانت‌اند نباید مستقیماً تراکنش بانکی بسازد یا نتیجهٔ پرداخت را بدون Verify سرور معتبر بداند.

### اینماد

پنل فقط فیلدهای کنترل‌شده می‌پذیرد:

- فعال‌بودن
- شناسه
- نشانی رسمی بررسی اعتبار
- نشانی تصویر نشان
- متن جایگزین
- محل نمایش

ورودی HTML یا JavaScript دلخواه برای اینماد مجاز نیست. Component فرانت‌اند فقط پیوند و تصویر تأییدشده را می‌سازد.

## Launch Readiness

`evaluateLaunchReadiness` دو نتیجهٔ جدا تولید می‌کند:

- `storefrontContentReady`: هویت، محل عمومی، راه ارتباطی و دادهٔ محصول برای تجربهٔ محتوایی آماده‌اند.
- `commerceLaunchReady`: ارسال، مرجوعی، پرداخت سرور، قوانین و دامنهٔ Production نیز کامل‌اند.

نداشتن آمادگی تجاری باید در پنل و فرایند انتشار گزارش شود؛ نه با پیام «نسخه نمایشی» در سایت مشتری.

## قواعد امنیتی

- هیچ Secret داخل `VITE_*` قرار نمی‌گیرد؛ متغیرهای `VITE_*` در Bundle مرورگر قابل مشاهده‌اند.
- هیچ `dangerouslySetInnerHTML` برای کد درگاه یا اینماد استفاده نمی‌شود.
- هیچ Raw HTML از پنل در Footer اجرا نمی‌شود.
- Callback پرداخت بدون Verify سمت سرور فقط یک ورودی غیرقابل اعتماد است.
- فعال‌سازی یک ادعا به‌تنهایی کافی نیست؛ وضعیت آن نیز باید `verified` باشد.

## معیار پذیرش

- تنظیمات عمومی Type-safe باشند.
- اسرار درگاه در Contract عمومی وجود نداشته باشند.
- نشان اینماد فقط به‌صورت کنترل‌شده نمایش داده شود.
- ادعاهای تأییدنشده خودکار پنهان شوند.
- چک‌لیست آمادگی فروش، موارد مسدودکننده را دقیق گزارش کند.
