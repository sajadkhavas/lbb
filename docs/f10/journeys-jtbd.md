# مخاطبان، JTBD و Journeyهای اصلی

## مخاطب ۱ — Drop Hunter

### مشخصات

- ۱۸ تا ۲۷ سال
- ورود عمدتاً از Instagram، پیام مستقیم یا لینک کمپین
- استفاده اصلی با موبایل
- تصمیم سریع و حساس به موجودی و سایز

### Job to Be Done

> وقتی یک Drop جدید می‌بینم، می‌خواهم سریع بفهمم چه قطعه‌هایی عرضه شده‌اند و آیا سایز و رنگ مناسب من موجود است تا قبل از تمام شدن تصمیم بگیرم.

### نیازها

- مشاهده سریع Drop
- تصویر On-body
- وضعیت سایز و رنگ
- قیمت و موجودی واضح
- Share و Wishlist
- مسیر کوتاه به PDP

### اصطکاک‌های محتمل

- Hero یا Campaign طولانی قبل از Product
- Navigation پنهان
- سایزهای داخل Select
- نبود Model Measurement
- Countdown یا Scarcity غیرقابل‌اعتماد

## مخاطب ۲ — Intent Shopper

### مشخصات

- ۲۰ تا ۳۴ سال
- ورود از Search، Category یا Recommendation
- مقایسه چند محصول
- حساس به فیت، جنس، Care و ارزش خرید

### Job to Be Done

> وقتی برای هودی یا شلوار مشخصی جستجو می‌کنم، می‌خواهم گزینه‌ها را بر اساس سایز، رنگ، قیمت و فیت محدود و مقایسه کنم تا با اطمینان انتخاب کنم.

### نیازها

- Search فارسی و لاتین
- Filter و Sort روشن
- حفظ State در Back/Forward
- Product Card قابل‌مقایسه
- Fit، Material و Care
- Related و Complete the Look

### اصطکاک‌های محتمل

- Grid هنری غیرقابل‌مقایسه
- Filter پنهان یا Applied State نامشخص
- برگشت از PDP و از دست رفتن Position
- اطلاعات محصول پراکنده
- تصاویر Campaign به جای تصویر واقعی Product

## مخاطب ۳ — Brand Explorer

### مشخصات

- ورود از Social، Share یا معرفی دوستان
- هنوز قصد خرید قطعی ندارد
- به Culture، Photography و Story علاقه دارد

### Job to Be Done

> وقتی برای اولین بار با LBB آشنا می‌شوم، می‌خواهم جهان، کیفیت و نگاه برند را بفهمم تا تصمیم بگیرم آن را دنبال یا محصولاتش را بررسی کنم.

### نیازها

- Hero واضح
- Manifesto کوتاه
- Lookbook و Collection Story
- Journal و Behind the Scenes
- مسیر طبیعی از Story به Product

### اصطکاک‌های محتمل

- متن برند عمومی و قابل‌استفاده برای هر فروشگاه
- Gallery بن‌بست
- افکت زیاد بدون داستان
- نبود ارتباط میان Look و Product

## مخاطب ۴ — Search-led Visitor

### مشخصات

- ورود مستقیم از Google به Product، Category یا Journal
- Homepage را ندیده است
- نیازمند Context و Navigation فوری

### Job to Be Done

> وقتی از نتیجه جستجو وارد یک صفحه داخلی می‌شوم، می‌خواهم سریع بفهمم این صفحه چیست، محصول یا مطلب چقدر معتبر است و مسیرهای مرتبط کدام‌اند.

### نیازها

- Title و H1 منطبق
- Breadcrumb
- تصویر و اطلاعات اولیه کامل
- لینک به Category، Product و Related Content
- Header و Footer قابل‌فهم بدون وابستگی به Homepage

### اصطکاک‌های محتمل

- صفحه داخلی بدون Context
- Structured Data یا اطلاعات تجاری غیرواقعی
- محتوای Editorial بدون لینک محصول
- Navigation وابسته به Hover

## مخاطب ۵ — Returning Keeper

### مشخصات

- قبلاً محصول دیده یا ذخیره کرده است
- با موبایل بازمی‌گردد
- می‌خواهد سریع State قبلی را بازیابی کند

### Job to Be Done

> وقتی دوباره به LBB برمی‌گردم، می‌خواهم محصولات ذخیره‌شده و اخیراً دیده‌شده را پیدا کنم و بدون شروع دوباره تصمیمم را ادامه دهم.

### نیازها

- Wishlist پایدار
- Recently Viewed
- Cart State معتبر
- Position و Filter History
- تغییر موجودی و سایز واضح

### اصطکاک‌های محتمل

- از بین رفتن State
- آیتم‌های قدیمی یا خراب Local Storage
- تفاوت رفتار Drawer و Page
- نبود Feedback برای تغییر وضعیت

# Journey ۱ — Social to Drop

## مسیر هدف

1. ورود از کمپین یا Social به Home/Collection
2. فهم Drop و CTA در اولین View
3. مشاهده Product Preview
4. ورود به PLP یا PDP
5. انتخاب Color و Size
6. Wishlist یا Add to Cart Preview

## معیار موفقیت

- CTA اصلی در اولین View دیده شود.
- Product در حداکثر سه تعامل قابل دسترسی باشد.
- Media نمایشی مانع Scroll یا Back نشود.
- روی موبایل هیچ Action ضروری پشت Hover نباشد.

# Journey ۲ — Search to Product

## مسیر هدف

1. ورود به Search یا استفاده از Global Search
2. تایپ فارسی، لاتین یا عبارت ناقص
3. مشاهده Suggestion، Recent و Category Intent
4. محدودکردن نتیجه با Filter
5. ورود به PDP
6. بازگشت و حفظ Query، Filter و Position

## معیار موفقیت

- غلط فاصله و نیم‌فاصله تحمل شود.
- Empty Result دلیل و مسیر جایگزین داشته باشد.
- Query و Filter در URL ذخیره شوند.
- Back/Forward State را بازگرداند.

# Journey ۳ — Category Comparison

## مسیر هدف

1. ورود به Category
2. مشاهده Result Count و Applied State
3. Filter بر اساس Size، Color، Availability و Price
4. تغییر Sort یا Density
5. مقایسه Cardها
6. ورود و بازگشت از PDP

## معیار موفقیت

- کنترل Filter و Sort در موبایل در Thumb Reach باشد.
- Clear All و حذف یک Filter در دسترس باشد.
- Card حداقل Name، Price، Variant Status و Product Media را حفظ کند.
- Load More پایان و وضعیت مشخص داشته باشد.

# Journey ۴ — Product Decision

## مسیر هدف

1. مشاهده تصویر اصلی و نام/قیمت
2. بررسی Front، Back، Detail، On-body و In-scale
3. مشاهده Fit و Model Measurement
4. انتخاب Color و Size
5. خواندن Material، Care و Shipping Preview
6. Wishlist، Share یا Add to Cart
7. مشاهده Related و Complete the Look

## معیار موفقیت

- سایز ناموجود قبل از Action مشخص باشد.
- خطای سایز نزدیک Selector و قابل اصلاح باشد.
- Sticky Buy Bar انتخاب فعلی را نمایش دهد.
- Swipe تنها مسیر تغییر تصویر نباشد.

# Journey ۵ — Editorial to Commerce

## مسیر هدف

1. ورود به Lookbook، Collection یا Journal
2. مصرف Story یا Image Sequence
3. مشاهده Product/Look Annotation
4. رفتن به Product یا Collection مرتبط
5. بازگشت به نقطه قبلی محتوا

## معیار موفقیت

- هیچ Editorial Page بن‌بست نباشد.
- Product Link واقعی و قابل Crawl باشد.
- بازگشت Position محتوا را حفظ کند.
- Linkها معنی روشن و Label قابل‌فهم داشته باشند.

# Journey ۶ — Returning Session

## مسیر هدف

1. ورود مجدد
2. مشاهده Wishlist یا Recently Viewed
3. بازیابی Product و Variant
4. بررسی تغییر موجودی
5. ادامه تصمیم

## معیار موفقیت

- داده خراب Storage باعث Crash نشود.
- آیتم حذف‌شده یا Slug نامعتبر پاک‌سازی شود.
- State قدیمی به‌عنوان موجودی قطعی نمایش داده نشود.

# سناریوهای تست وظیفه‌محور F22

1. «یک هودی مشکی موجود در سایز L پیدا کن و ذخیره کن.»
2. «از Search یک تیشرت را پیدا کن، واردش شو و به همان نتایج برگرد.»
3. «از Lookbook یک استایل را باز کن و محصول مربوط را پیدا کن.»
4. «بفهم این شلوار روی چه قد و سایزی نمایش داده شده و چگونه باید شسته شود.»
5. «یک Filter را اعمال کن، یکی را حذف کن و همه را پاک کن.»
6. «بدون ماوس Gallery، Menu، Search و Size Guide را استفاده کن.»
7. «با Reduced Motion و Zoom دویست درصد مسیر Product را کامل کن.»
8. «از یک مقاله وارد Product مرتبط شو و دوباره به همان بخش مقاله برگرد.»

# رویدادهای پیشنهادی Analytics

این رویدادها پس از فراهم شدن Analytics و رضایت کاربر پیشنهاد می‌شوند:

- `nav_category_open`
- `search_submit`
- `search_no_result`
- `filter_apply`
- `filter_clear`
- `product_open`
- `gallery_media_change`
- `size_guide_open`
- `size_select`
- `wishlist_toggle`
- `cart_preview_add`
- `editorial_product_click`
- `recently_viewed_open`

هیچ داده حساس، متن آزاد فرم یا اطلاعات شخصی نباید در Eventها ثبت شود.
