# F10 — Research and Experience North Star

تاریخ ثبت: ۲۰۲۶-۰۸-۰۴

این پوشه تصمیم‌های تحقیقاتی و تجربه‌ای مرحله F10 پروژه LBB را ثبت می‌کند. هدف این فاز تغییر کد رابط نبود؛ هدف، تعیین یک جهت واحد و قابل‌اندازه‌گیری برای تمام فازهای طراحی و توسعه بعدی بود تا پروژه به مجموعه‌ای از افکت‌ها یا صفحه‌های نامنسجم تبدیل نشود.

## North Star نهایی

**Tehran After Dark — Editorial Utility**

LBB باید مانند یک مجله خیابانی زنده از تهران احساس شود، اما خرید و پیدا کردن محصول باید به وضوح یک ابزار حرفه‌ای و سریع باقی بماند.

ترکیب هدف:

- ۷۰٪ وضوح محصول، ناوبری و تصمیم خرید
- ۲۰٪ روایت ادیتوریال و فرهنگ برند
- ۱۰٪ نمایش خلاقانه و لحظه‌های Wow

## تصمیم‌های قطعی

1. LBB یک «فروشگاه با شخصیت ادیتوریال» است، نه یک Portfolio هنری با سبد خرید.
2. موبایل و RTL نسخه اصلی تجربه‌اند؛ دسکتاپ نسخه توسعه‌یافته آن است.
3. هیچ حرکت، WebGL، ویدئو یا سه‌بعدی مجاز نیست مسیر خرید، دسترس‌پذیری یا Core Web Vitals را ضعیف کند.
4. محصول، اندازه، رنگ، جنس، فیت، تصویر و وضعیت موجودی باید همیشه از نمایش بصری مهم‌تر باشند.
5. هر صفحه حداکثر یک لحظه نمایشی اصلی دارد؛ سایر حرکت‌ها باید وظیفه ارتباطی مشخص داشته باشند.
6. هیچ الگوی مخفی، Hover-only، Scroll Hijacking، کمیابی جعلی یا اعتمادسازی ساختگی پذیرفته نیست.
7. صفحات ادیتوریال باید به محصول، کالکشن یا موضوع بعدی لینک واقعی بدهند؛ محتوای بن‌بست پذیرفته نیست.
8. SEO، Performance و Accessibility ویژگی‌های نهایی نیستند؛ Guardrail تمام فازها هستند.

## معیار قبولی Experience North Star

هر پیشنهاد آینده باید بتواند به این پنج پرسش پاسخ دهد:

1. کدام نیاز یا اصطکاک کاربر را حل می‌کند؟
2. چگونه هویت LBB را متمایزتر می‌کند؟
3. آیا روی موبایل، RTL، کیبورد و Reduced Motion کار می‌کند؟
4. هزینه آن برای LCP، INP، CLS و حجم JavaScript چیست؟
5. با کدام معیار یا تست می‌توان موفقیت آن را سنجید؟

پیشنهادی که پاسخ روشن نداشته باشد وارد Backlog اجرایی نمی‌شود.

## وضعیت پایه پروژه در شروع F10

پروژه هنگام شروع این فاز دارای مسیرهای کامل Home، Shop، Category، Search، Product، Cart، Checkout Preview، Collections، Lookbook، Journal و صفحات پشتیبان بود. Quality Pipeline نیز Build، TypeScript، ESLint، Audit، Cloudflare Worker Smoke، Axe، SEO/PWA، History و Visual Regression را پوشش می‌داد.

بنابراین F10 به جای بازسازی زیرساخت، روی تعریف کیفیت نسل بعدی Frontend متمرکز شد.

## Handoff به فازهای بعدی

- F11 باید Design System 2.0 را بر اساس Art Direction منتخب بسازد.
- F12 باید Global Shell را با اصل «وضوح قبل از نمایش» بازطراحی کند.
