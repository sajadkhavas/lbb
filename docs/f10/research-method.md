# روش تحقیق F10

## هدف

این تحقیق برای پاسخ به یک پرسش انجام شد:

> چگونه LBB می‌تواند از نظر بصری بسیار متمایز باشد، بدون اینکه سرعت، قابلیت استفاده، دسترس‌پذیری و قابلیت کشف محصول قربانی شوند؟

## دامنه بررسی

تحقیق در پنج جریان انجام شد:

1. پژوهش‌های عمومی UX و Usability
2. پژوهش‌های تخصصی Ecommerce و Apparel
3. استانداردهای Accessibility و Performance
4. راهنمای رسمی Ecommerce SEO
5. بررسی جهت‌دار وب‌سایت‌های مد، استریت‌ویر، Luxury و Utility Commerce

## منابع مرجع

### UX و Usability

- [Nielsen Norman Group — 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)
- [Nielsen Norman Group — Animation for Attention and Comprehension](https://www.nngroup.com/articles/animation-usability/)

اصول استخراج‌شده:

- وضعیت سیستم باید قابل مشاهده باشد.
- کاربر باید کنترل و امکان بازگشت داشته باشد.
- ثبات اصطلاحات و رفتارها ضروری است.
- Recognition بر Recall ترجیح دارد.
- مینیمالیسم به معنی حذف اطلاعات لازم نیست.
- حرکت فقط زمانی ارزش دارد که توجه، رابطه یا تغییر وضعیت را توضیح دهد.

### Apparel Ecommerce UX

- [Baymard — Apparel and Accessories UX Benchmark 2025](https://baymard.com/blog/apparel-and-accessories-ux-benchmark-2025)
- [Baymard — Apparel Ecommerce UX Research](https://baymard.com/research/apparel-and-accessories)
- [Baymard — Ecommerce UX Benchmark](https://baymard.com/ux-benchmark)
- [Baymard — Direct-to-Consumer Benchmark](https://baymard.com/ux-benchmark/collections/direct-to-consumer)

اصول استخراج‌شده:

- Navigation، Search، Product List، Filter، PDP و Cart باید یک سیستم واحد باشند.
- تصاویر، فیت، سایز، رنگ و موجودی برای پوشاک اطلاعات تصمیم‌ساز هستند.
- Applied Filterها، نتیجه فیلتر، Clear All و بازگشت به Grid باید واضح باشند.
- نسخه موبایل نیازمند طراحی مستقل برای Filter، Sort، Search و Product List است.
- زیبایی Card نباید ویژگی‌های لازم برای مقایسه محصول را حذف کند.

### Accessibility

- [W3C — WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- [W3C — What is new in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)

اصول استخراج‌شده:

- Focus نباید پشت Header، Drawer یا Sticky UI مخفی شود.
- Drag و Swipe باید جایگزین Single Pointer داشته باشند.
- Targetهای لمسی باید حداقل استاندارد را پاس کنند و برای کنترل‌های اصلی به ۴۴×۴۴ نزدیک شوند.
- Label، Role، Name، ترتیب Focus و بازگرداندن Focus جزو قرارداد Component هستند.

### Ecommerce SEO

- [Google Search Central — Ecommerce Best Practices](https://developers.google.com/search/docs/specialty/ecommerce)
- [Google — Ecommerce Site Structure](https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure)

اصول استخراج‌شده:

- تمام محصولات قابل Index باید از لینک‌های واقعی Navigation و Category قابل دسترسی باشند.
- Search Box جایگزین Internal Linking نیست.
- Faceted Navigation باید Crawl Space کنترل‌شده داشته باشد.
- Structured Data باید وضعیت واقعی محصول و تجارت را منعکس کند.
- صفحات Editorial باید با Internal Link به Category و Product مرتبط شوند.

## روش Benchmark

سی وب‌سایت در سه گروه انتخاب شدند:

- برندهای Creative و Streetwear
- Luxury و Editorial Commerce
- سایت‌های Utility و Research-backed Ecommerce

هر سایت با شش شاخص جهت‌دار از ۱ تا ۵ بررسی شد:

- BI: قدرت و تمایز هویت برند
- DC: کیفیت Discovery، Category، Search و Catalog
- PDP: کیفیت تصمیم‌سازی صفحه محصول
- MO: کیفیت تجربه موبایل
- ED: قدرت Editorial Storytelling
- RL: میزان ارتباط الگوها با LBB

این امتیازها نتیجه تست کنترل‌شده کاربر نیستند. آن‌ها Expert Review جهت‌دار برای انتخاب الگو و جلوگیری از Copy مستقیم‌اند.

## بررسی کد فعلی LBB

تحقیق خارجی با ممیزی پیاده‌سازی فعلی ترکیب شد:

- Homepage در حال حاضر Hero و دوازده بخش روایی/تجاری دارد.
- Shop دارای URL Filter پایدار، Sidebar دسکتاپ، Drawer موبایل و Load More است.
- Search دارای Recent Search، Filter و URL History است، اما Typo، Synonym و Intent Grouping ندارد.
- PDP دارای Gallery، Color، Size، Wishlist، Sticky Buy Bar، Fit Guide و Related Product است، اما Model Measurement، Material Story، Complete the Look و Media Depth هنوز محدود است.
- Visual Regression فقط هشت Baseline دارد و تمام خانواده‌های Route و State را پوشش نمی‌دهد.

## محدودیت‌های تحقیق

- دسترسی به Analytics، Search Console و داده رفتار واقعی کاربران LBB وجود نداشت.
- تست مصاحبه‌ای یا مشاهده‌ای با مخاطب ایرانی در F10 انجام نشد.
- برخی سایت‌ها بر اساس منطقه جغرافیایی، موجودی یا کمپین روز تغییر می‌کنند.
- امتیاز Benchmark برای تصمیم طراحی است و ادعای رتبه‌بندی علمی سایت‌ها نیست.

## فرضیه‌های نیازمند اعتبارسنجی کاربر

1. مخاطب LBB ابتدا با موبایل و از Social وارد می‌شود.
2. سایز و تصویر روی مدل بزرگ‌ترین مانع تصمیم خرید هستند.
3. کاربران به روایت تهران علاقه دارند، اما Navigation پنهان را تحمل نمی‌کنند.
4. Lookbook می‌تواند مسیر ورود به Product باشد، نه یک Gallery بن‌بست.
5. Search فارسی باید غلط تایپی، فاصله، نیم‌فاصله و نام لاتین محصول را تحمل کند.

این فرضیه‌ها باید در F22 با تست وظیفه‌محور و پس از انتشار با Analytics تأیید یا رد شوند.
