# قانون اساسی تجربه LBB

## North Star

**Tehran After Dark — Editorial Utility**

LBB باید مانند یک مجله خیابانی زنده از تهران احساس شود؛ اما پیدا کردن، فهمیدن و انتخاب محصول باید سریع، واضح و قابل‌اعتماد بماند.

## نسبت تجربه

- ۷۰٪ Commerce Clarity
- ۲۰٪ Editorial Narrative
- ۱۰٪ Creative Spectacle

این نسبت برای تمام صفحه‌ها یکسان نیست، اما میانگین کل تجربه باید آن را حفظ کند.

## هفت ستون تجربه

### ۱. Raw Precision

ظاهر باید خام، شهری و قاطع باشد؛ اجرا باید دقیق، منظم و بدون بی‌نظمی ناخواسته باشد.

- Grid، Alignment و Rhythm باید قابل‌اندازه‌گیری باشند.
- Texture و Grain فقط در سطح تصویری یا Accent استفاده می‌شوند.
- آشفتگی بصری نباید با «خیابانی بودن» توجیه شود.

### ۲. Product Truth

هیچ عنصر بصری نباید اطلاعات تصمیم خرید را پنهان کند.

- تصویر، سایز، رنگ، فیت، جنس، Care و وضعیت موجودی اولویت دارند.
- اطلاعات نامطمئن یا Demo باید صریح علامت‌گذاری شوند.
- Review، Countdown، Scarcity، Shipping و Trust Signal ساختگی ممنوع‌اند.

### ۳. Tehran Narrative

هویت LBB باید از تهران، زبان فارسی، ریتم خیابان و فرهنگ واقعی مخاطب ساخته شود؛ نه از تقلید ظاهری سایت‌های غربی.

- لحن فارسی باید طبیعی، کوتاه و قابل‌فهم باشد.
- انگلیسی فقط برای Tech Label، SKU، Drop Code و Accent مجاز است.
- Photography باید مکان، نور، بافت و انرژی محلی داشته باشد.

### ۴. Motion with Meaning

حرکت فقط برای توضیح رابطه، تغییر وضعیت، جهت یا اولویت استفاده می‌شود.

- هر صفحه حداکثر یک Moment نمایشی اصلی دارد.
- Microinteraction باید در محدوده ۱۵۰ تا ۳۵۰ میلی‌ثانیه باقی بماند، مگر روایت خاص.
- هیچ Transition نباید Action کاربر را به تأخیر بیندازد.
- Reduced Motion باید تجربه کامل و نه نسخه ناقص ارائه دهد.

### ۵. Frictionless Commerce

کاربر باید بدون یادگیری رابط بتواند محصول مناسب را پیدا و ارزیابی کند.

- دسته، Search، Filter، Sort، Wishlist و Cart همیشه قابل کشف‌اند.
- وضعیت Applied Filter و نتیجه تغییر باید واضح باشد.
- بازگشت از PDP باید Position و State Grid را حفظ کند.
- خطاها باید نزدیک کنترل مربوطه، قابل‌فهم و قابل‌اصلاح باشند.

### ۶. Inclusive by Default

Accessibility یک Style Mode نیست؛ قرارداد پایه Component است.

- Keyboard، Touch، Pointer و Screen Reader باید مسیرهای معادل داشته باشند.
- Focus باید واضح، دارای کنتراست و همیشه قابل مشاهده باشد.
- Swipe و Drag باید دکمه یا Tap Alternative داشته باشند.
- Zoom، Reflow، RTL و متن بلند نباید Layout را بشکنند.

### ۷. Searchable Story

هر داستان باید قابل کشف و هر محصول باید از چند مسیر قابل دسترسی باشد.

- Home، Category، Collection، Journal و Lookbook باید Internal Link واقعی بدهند.
- Search Box تنها مسیر کشف محصول نیست.
- محتوای Editorial بن‌بست ممنوع است.
- Canonical، Structured Data و Indexation باید با واقعیت صفحه هماهنگ باشند.

## وعده‌های تجربه

### وعده اول: فهم برند در ده ثانیه

کاربر جدید باید در اولین View بفهمد:

- LBB چیست.
- چه نوع محصولی ارائه می‌کند.
- شخصیت بصری آن چیست.
- اقدام اصلی بعدی کدام است.

### وعده دوم: رسیدن به محصول در سه تعامل

از Home یا Navigation، کاربر باید حداکثر در سه تعامل به Product List یا Product Detail مرتبط برسد.

### وعده سوم: تصمیم‌سازی در شصت ثانیه

PDP باید در کمتر از یک دقیقه پاسخ دهد:

- این محصول چه شکلی است؟
- روی بدن چگونه می‌ایستد؟
- جنس و حس آن چیست؟
- کدام سایز و رنگ موجود است؟
- چگونه نگهداری می‌شود؟
- آیا با استایل یا محصول دیگری کامل می‌شود؟

### وعده چهارم: State قابل اعتماد

کاربر باید همیشه بداند:

- کدام Filter فعال است.
- چه چیزی به Wishlist یا Cart اضافه شده است.
- چرا نتیجه‌ای وجود ندارد.
- کدام قابلیت واقعی و کدام Preview است.
- چگونه به حالت قبلی بازگردد.

### وعده پنجم: زیبایی بدون جریمه

هیچ ویژگی هنری مجاز نیست:

- LCP را از هدف عبور دهد.
- INP را کند کند.
- Layout Shift ایجاد کند.
- Focus یا متن را مخفی کند.
- Navigation را مبهم کند.
- روی دستگاه ضعیف تجربه را از کار بیندازد.

## قوانین صفحه

### Homepage

- فقط یک Hero اصلی و یک Moment ثانویه نمایشی.
- هر Section باید نقش Discovery، Decision، Story یا Trust داشته باشد.
- Section تکراری یا بدون مسیر بعدی حذف می‌شود.

### Product List

- تصویر و اطلاعات لازم برای مقایسه باید هم‌زمان دیده شوند.
- Filter، Sort، Result Count و Applied State یک سیستم واحد هستند.
- Density می‌تواند تغییر کند، اما Product Card نباید اطلاعات حیاتی را از دست بدهد.

### Product Detail

- Media و Decision Panel باید در موبایل و دسکتاپ اولویت درست داشته باشند.
- Size و Availability نباید داخل Select پنهان شوند.
- Material، Fit و Care باید بخشی از تجربه و نه Footer متن باشند.

### Editorial

- متن باید Readable Width، ساختار Heading و مسیر ادامه داشته باشد.
- Lookbook باید Shoppable باشد.
- مقاله باید Product، Collection یا مقاله مرتبط پیشنهاد دهد.

### Overlay و Modal

- Focus Trap، Escape، Focus Restoration و Scroll Lock اجباری‌اند.
- Overlay نباید مسیر اصلی تنها برای انجام یک کار ساده باشد.

## Anti-goalها

LBB نباید تبدیل شود به:

- یک Awwwards Clone با Scroll اجباری
- یک داشبورد Ecommerce عمومی با رنگ قرمز
- یک سایت Luxury خنثی و بی‌هویت
- یک تجربه Cyberpunk کلیشه‌ای
- یک Homepage بسیار طولانی از Sectionهای مستقل
- یک نمایش سه‌بعدی بدون ارزش خرید
- یک نسخه دسکتاپ که در موبایل جمع شده است

## Decision Filter

هر Feature یا تغییر طراحی پیش از اجرا باید از این فیلتر عبور کند:

1. هدف کاربر چیست؟
2. State قبل، حین و بعد چیست؟
3. جایگزین Keyboard و Reduced Motion چیست؟
4. اثر آن روی Product Clarity چیست؟
5. هزینه Performance آن چیست؟
6. چگونه تست می‌شود؟
7. آیا به هویت Tehran After Dark کمک می‌کند یا فقط Trend است؟

اگر پاسخ روشن وجود نداشته باشد، Feature وارد اجرا نمی‌شود.

## معیارهای موفقیت آینده

پس از انتشار و اتصال Analytics، این معیارها باید اندازه‌گیری شوند:

- نرخ رسیدن Home به PLP/PDP
- استفاده و موفقیت Search
- نرخ Empty Result
- استفاده Filter و Clear All
- بازگشت PDP به Grid با State حفظ‌شده
- تعامل با Size Guide و Material Detail
- Editorial-to-Product Click-through
- Wishlist و Add-to-cart Intent
- LCP، INP و CLS صدک ۷۵
- خطاهای JavaScript و Accessibility Regression
